# Glossary & Concepts 📖

This document provides plain-language definitions for the core vocabulary and technical concepts used throughout the Meeseek platform.

---

## 1. Core Substrate & Sandboxing

| Term | Definition |
|---|---|
| **Golden Image / Golden Build** | The master, pre-built, and pre-seeded copy of an application's world: repositories, container images, dependencies, and migrated database files with seed fixtures. Built once (on merges to main or scheduled rebuilds) and never booted directly—every workspace is an instant clone of it. |
| **Copy-on-Write (CoW) Reflink** | An OS-level filesystem feature where two directories share the same physical disk blocks until one modifies data. On Linux XFS/btrfs, this uses `cp --reflink=always`; on macOS, this uses APFS `clonefile`. Enables cloning gigabytes of database and code state in **under 300 milliseconds**. |
| **Strike** | The act of CoW-cloning the golden image into an isolated, per-task workspace and booting its Docker Compose project. Named after striking a coin from a die. Takes ~12–30 seconds from cold, or ~50ms from a warm pool. |
| **Workspace** | A single task's disposable sandbox—a dedicated folder on disk (`$HOLO_WORKSPACES/<lease_id>`) and an isolated Docker Compose project (`ws-<lease_id>`). Discarded completely upon task completion. |
| **Lease** | The API checkout unit representing a claimed workspace. Managed by `LeaseService`, carries a Time-To-Live (TTL), and is automatically cleaned up by the background `LeaseReaper` if abandoned. |
| **Warm Pool** | A small pool of pre-struck, idle workspaces maintained by `PoolManager`. When a task arrives, claiming a warm slot takes only a git branch cut (~50ms) instead of waiting for container boots. |
| **Port Stripping** | A Docker Compose override technique (`ports: !reset []`) that strips all published host ports from databases, caches, and internal microservices. Only the designated web entrypoint is re-exposed on a dedicated preview port, eliminating port collisions between concurrent workspaces. |
| **Live Preview URL** | A dynamic HTTPS URL (e.g. `https://p18001.preview.domain.com`) routed through an automated TLS reverse proxy (Caddy), allowing human engineers to review UI and API changes directly in a browser without pulling code locally. |

## 2. Verification & Quality Engineering

| Term | Definition |
|---|---|
| **Host-Side Notary (`finalize`)** | Meeseek's independent verification engine. Enforces the rule *"The actor that does the work never certifies it."* Meeseek executes container health probes, runs SQL seed-verification queries, captures authentic test exit codes, and extracts the genuine git diff outside of agent control. |
| **Evidence Bundle (`PR.md`)** | The tamper-proof summary generated by the Notary and attached to the GitHub Pull Request, detailing endpoint status, SQL query outputs, raw test logs, and the exact diff. |
| **AST Delta Tracking** | Syntactic analysis that parses modified code into Abstract Syntax Trees before and after an edit. Catches subtle agent shortcuts, such as deleting assertions from failing test files or stripping `@require_auth` decorators. |
| **Self-Healing Loop** | An automated remediation flow where test failures (detected by the Notary or GitHub Actions CI) or reviewer comments are synthesized into actionable feedback and fed back to the agent in the running sandbox to iteratively fix issues. |
| **Circuit Breaker** | Deterministic guards (such as a maximum retry budget of 2 attempts) that stop execution and alert a human if a task hits an unrecoverable environmental error or infinite remediation loop. |

## 3. Agent Orchestration & Coordination

| Term | Definition |
|---|---|
| **Omnigent** | The open-source agent orchestration harness that manages the LLM reasoning loop, tool invocation policies, and agent execution sessions. |
| **Sandbox Provider Wheel** | The Python plugin package (`omnigent-community-sandbox-meeseek`) baked into the Omnigent container that translates Omnigent's `provision()` and `exec()` primitives into HTTP calls against Meeseek's `/leases` API. |
| **Elicitation (`waiting-input`)** | An interactive state where an agent detects ambiguity in requirements or technical trade-offs and pauses execution to post a clarifying question to the human developer in the GitHub/Jira/Slack thread. |
| **`ConsoleManager`** | The central state coordinator in the Meeseek Control Plane that correlates one ticket/issue with one lease and one agent session, handling human replies, status rollups, and PR publishing. |
| **`WorkspaceProvider`** | The Python interface (`holodeck/providers/base.py`) separating the control plane from the underlying compute substrate. Enabled today via `ComposeProvider` (Docker Compose on host) and mockable via `FakeProvider`. |
